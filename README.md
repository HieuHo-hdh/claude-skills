# claude-skills

A workspace of **`fe-*` skills** and shared **rules** that guide Claude Code through frontend engineering tasks — scaffolding, style tokens, components, pages, auth, restyles — plus example projects generated by those skills under `source-code/`.

## Layout

```
.claude/
├── skills/           ← invocable workflows (imperative)
│   ├── fe-setup/
│   ├── fe-auth/
│   ├── fe-boilerplate/
│   ├── fe-component/
│   ├── fe-page/
│   └── fe-restyle/
└── rules/            ← shared conventions (declarative)
    ├── fe-workspace-layout.md
    ├── fe-responsive.md
    ├── fe-a11y.md
    ├── fe-coding-conventions.md
    └── markdown-style.md

source-code/          ← projects generated by fe-setup (each has its own CLAUDE.md)
```

## Skills

Invoke a skill with `/<name>` in Claude Code (e.g. `/fe-setup`). Each skill has its own `SKILL.md` with a full workflow and prerequisites.

| Skill               | When to use                                                                                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`fe-setup`**      | Scaffold a new frontend project from scratch. Walks through language / framework / UI library / router / state / lint / test selections.                        |
| **`fe-auth`**       | Wire authentication: token storage (SPA vs Next.js BFF), axios interceptors with a shared refresh promise, guard component, store slice.                        |
| **`fe-boilerplate`**| After `fe-setup`, scaffold starter pages (landing / admin portal / custom). Derives Style tokens on first run. Auth pages stubbed if `fe-auth` was skipped.     |
| **`fe-component`**  | Build one reusable UI component from a brief. Props API first, then variants, states, a11y, one unit test.                                                      |
| **`fe-page`**       | Build one full page / route from a spec. Registers route, composes layout, wires data with loading / error / empty / success, ships one smoke test.             |
| **`fe-restyle`**    | Change the visual direction of an existing project. Derives new tokens, updates `CLAUDE.md`, migrates UI theme-first.                                           |

### Typical flow

```
fe-setup ──► fe-boilerplate ──► fe-auth (optional) ──► fe-component / fe-page ──► fe-restyle (later)
```

Style tokens are derived and written to `CLAUDE.md`'s Style section by `fe-boilerplate`'s step 0 (first UI scaffold) and rewritten by `fe-restyle` on direction change.

## Rules

Rules are **declarative conventions** read by skills — not invoked directly. When a skill says *"Full rule: `.claude/rules/<name>.md`"* it means those constraints apply during the workflow.

| Rule                          | Applies to                                                          |
| ----------------------------- | ------------------------------------------------------------------- |
| **`fe-workspace-layout.md`**  | Where projects live (`source-code/<name>/`), sibling isolation. **All `fe-*` skills read this.** |
| **`fe-responsive.md`**        | Mobile-first, breakpoint scale, touch targets, `100dvh` vs `100vh`, three-width sanity check (375 / 768 / 1280). |
| **`fe-a11y.md`**              | Semantic HTML, ARIA only when semantics fall short, keyboard patterns, focus management, WCAG AA contrast, `prefers-reduced-motion`. |
| **`fe-coding-conventions.md`**| Naming (`PascalCase` / `camelCase` / kebab files), import order, TypeScript (`interface` vs `type`, no `any`), comment discipline, error at boundaries only. |
| **`markdown-style.md`**       | How `.md` files are shaped: title + scope line, `## Contents` block, canonical skill-file layout, tables over prose lists, `✅ / ❌` code fences, anti-pattern lists. |

`markdown-style.md` applies to every `.md` file authored under this repo, so every skill's `SKILL.md` follows it by construction.

## Naming policy

- Frontend skills and frontend-only rules use the **`fe-`** prefix.
- Cross-cutting rules that apply to every doc (e.g. `markdown-style.md`) skip the prefix.
- Non-frontend rules / skills added later (backend, infra, tooling) get their own prefix and must **not** collide with the `fe-*` namespace.
- Skills are **imperative** (`fe-verb-noun`); rules are **declarative** (`fe-noun`).

## Adding a new skill

1. Create `.claude/skills/<name>/SKILL.md` with YAML frontmatter (`name`, `description`). Follow the fixed layout in `.claude/rules/markdown-style.md` → Skill file layout.
2. Add `## Prerequisites`, `## Working directory`, `## Shared conventions` (pointer to the rule files that apply), and a numbered `## Workflow`. Canonical section names: `Prerequisites`, `Input`, `Output`, `Verification`.
3. Reference existing rules via `` `.claude/rules/<rule>.md` `` — do not restate their content.
4. Update this README's Skills table and the coverage matrix.

## Adding a new rule

1. Create `.claude/rules/<name>.md` — prefix `fe-` if it is frontend-only, no prefix if cross-cutting.
2. Add a one-line scope line stating what it covers and which skills consume it.
3. Update the *Which rules each skill enforces* table and add a `Shared conventions` bullet in every skill that should follow it.
